### レイアウト編集でできること（詳細）

- **区画の移動・リサイズ**（ドラッグ／つまみ／数値入力）
- **部品ごとの最小サイズを自動計算**し、それより小さくできない。
  計算は実データから（キーボードは列数・行数と一番細いキーのcolSpan、
  Deckは格子とスロット数）。基準端末は iPad Pro 12.9 横、タップ下限44px
- **重なり・はみ出しは確定させない**。ドラッグ中は赤く見せ、指を離すと元へ戻す。
  数値入力・手動下限の変更・部品の追加も同じ扱い
- **部品をパレットへ戻す**。掴んだまま「置ける部品」へ放り込む
  （狭い画面ではその口が画面上端へ貼り付く）
- **区画の中に実物のプレビュー**が出る。実機と同じ `components.js` で描いているので
  プレビューと実機の絵が食い違わない
- **共有されている部品の警告**。「この部品は他の N 件でも使われています」
- **編集中レイアウトのQR**をヘッダから出せる（別レイアウトのQRを読む取り違えを防ぐ）
- **保存**。`layouts/layout_<id>.json` へ書き戻し、繋がっている端末へ即反映

## 3. 保存の防御

書き込みは `POST /api/layout/save` の1本のみ。不変条件6を拡張した際、
条文に防御条件を明記した。

1. 書き先は `layouts/layout_<layoutId>.json` 固定。**ファイル名は受け取らない**
2. `layoutId` は `[a-z0-9_]{1,64}` のみ（`ws::layout_id_is_safe`）。
   **パスを組み立てる前の唯一の関門**
3. 受け取った本文はそのまま書かず、解釈し直して整形したものを書く
4. `.bak` を取ってから書く
5. **書いた後に全体を読み直して検証**し、通らなければ巻き戻す

実測での確認:

| 試したこと | 結果 |
|---|---|
| `layoutId: "a/b"` | 422（ファイル名になる前に拒否） |
| `layoutId: "../evil"` | 422 |
| 区画の重なり | 422「A と B が (row 1, col 2) で衝突」 |
| 存在しない `ref` | 422。書いた後に落ちて `rolledBack: true` |

4回の不正保存のあと `layouts/` に**残骸ゼロ**。
