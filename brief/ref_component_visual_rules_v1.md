# 部品の見た目のルール v1（色とアイコン）

制定: 2026-09-06 ／ 対象: 区画エディタ・Hub設定画面・レイアウト面
状態: **v1 制定。以降、部品種別を増やすときは必ずここを更新すること**

---

## 1. 色は「何を送る部品か」で決める

部品の色を見た目の好みで決めない。**その部品がHubへ送るメッセージの種別**に対応させる。
種別は `crates/proto-hub/src/protocol.rs` の `ClientMessage` にある3つ。

| 色 | 送るメッセージ | 意味 | 該当する部品 |
|---|---|---|---|
| **青** | `key.press` | キーを押す・離す | 一枚キーボード、十字キー |
| **紫** | `deck.press` | コマンドを1回発火する | Stream Deck、コピペリスト |
| **緑** | `surface.state` | 連続した値を出し続ける | トラックボール |

### なぜこの決め方か

見た目の分類と、実際の通信の分類が**ずれない**。
「十字キーは青か緑か」で迷ったら、`key.press` を送っているかを見れば決まる。
実際、十字キーは3×3の小さなboardを持つキーボードでしかなく、`key.press` を送る。だから青。

**部品種別を増やすときの判定**: 新しい部品がどのメッセージを送るかを先に決める。
3つのどれにも当てはまらないなら、それは新しいメッセージ種別の追加であり、
**色より先に不変条件1（クライアントが送ってよいもの）の裁定が要る**。

### 色の値

```css
--kind-key:   #2b4a7a;   /* 青  key.press   */
--kind-cmd:   #4a2f66;   /* 紫  deck.press  */
--kind-state: #1c4d47;   /* 緑  surface.state */
```

区画の塗りに使う。文字は白（`--ink`）で読める明度に保つこと。

## 2. 色を他の意味に流用しない

**部品ではないものに、部品の色を使わない。色を持つのは部品種別だけ。**

| 出てくるもの | 部品種別か | 色 |
|---|---|---|
| レイアウトの区画の `kind` | **そう** | §1 の3色 |
| 接続先の種別（kb / deck / ipad / trackball / panel / layout） | 違う（**画面の入口**） | 中立の灰 |
| Deckの描き方（grid / list） | 違う（**描き方**） | 中立の灰 |
| キーマップの種別（split / single） | 違う（盤の形） | 中立の灰 |

中立の灰: `background:#2a3352; color:var(--ink-muted); border:1px solid var(--line)`

**適用済み（2026-09-06）**。以前 `settings.html` が `layout` に青を使っており、
青＝`key.press`（キーボード）と意味が衝突していた。ユーザー裁定「入り口は灰色」により解消。

### 明るさの方針（ユーザー指定）

**白い画面にしない。** 暗い背景を既定とする（`color-scheme: dark`、背景は `#101526` 前後）。
新しい画面を足すときも同じ土台に合わせること。

## 3. 色だけに意味を載せない（アイコンを併用する）

色が見分けにくい人にも、モノクロ印刷でも通じるようにする。
**色とアイコンは常に同じ分類を指す**（片方だけ見れば分かる状態にする）。

| 分類 | アイコン | 形の由来 |
|---|---|---|
| 青 `key.press` | キーボードの輪郭＋3段のキー | 押す面が並んでいる |
| 紫 `deck.press` | 3×2 の四角 | Stream Deckの格子 |
| 緑 `surface.state` | 円＋中心の点 | 転がる球 |

### 実装のきまり

- **インラインSVG**で描く。アイコンフォント・外部画像・CDNは使わない（D2）
- `fill="currentColor"` / `stroke="currentColor"` にして、**色はCSSから与える**。
  アイコン側に色を焼き込まない（同じ形を別の文脈で使い回せなくなる）
- viewBox は `0 0 16 16`、表示は 14px 前後
- 絵文字は使わない。端末ごとに字形が変わり、iPadとPCで見え方が揃わない

> 比較パネルのSVGは削除したが、アイコンにSVGを使うのは矛盾しない。
> SVGが向くのは**動かさない絵**であり、アイコンはまさにそれ（DEVBOARD T32 の結論どおり）。

---

## 4. 数字は装飾しない

パレットに出している「最小 5×2」は**データ**であって飾りではない。
色やアイコンで代用せず、数字のまま出す。基準端末（iPad Pro 12.9 横）が変われば
この数字も変わるため、根拠（1マスの実寸・タップ下限）を画面のどこかに残しておくこと。
