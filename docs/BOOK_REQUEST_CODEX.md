## 0. 最初に読む — 依頼の前提が1つ崩れています

ご依頼は **「Tauri + Rust + custom keyboard の作り方」** でした。
しかし**このリポジトリに Tauri は1行も使われていません。**

```
検索結果: Cargo.toml / Cargo.lock / crates/*/Cargo.toml に "tauri" は 0件
```

実際の構成:

| 層 | 実体 |
|---|---|
| PC側（Hub） | Rustワークスペース。**axum 0.8**（HTTP＋WebSocket）＋ tokio ＋ `windows` crate の **SendInput** |
| 端末側 | **素のHTML+JS**（ブラウザ）。フレームワーク・ビルド工程・CDN依存はゼロ |
| つなぎ | LAN内のWebSocket 1本。token認証（起動ごとに再生成） |

しかもリポジトリの憲法（`CLAUDE.md`）は次を**確定アーキテクチャ**として定めています。

> React Native不使用・素のWeb端末＋Rust Hub という現行方式は確定アーキテクチャであり、提案なしに変更してはならない
> D2: PWA機構・フロントフレームワーク・ビルドツール・CDN依存の導入禁止（端末は素のHTML+JS）

**したがって、このコードから「Tauriの作り方」を書くことはできません。**
書けば、動かないコードか、リポジトリに存在しない架空の実装を載せることになります。

## 1. この題材の何が本になるのか

チュートリアルとしての価値は高くありません（似た記事は多い）。
**価値があるのは、実際に踏んだ落とし穴と、その理由**です。以下はすべて
`DEVBOARD.md` に日付・検証記録つきで残っている**実話**です。作り話ではありません。

| # | 落とし穴 | なぜ面白いか |
|---|---|---|
| 1 | **許可リストが入れ子のアクションを見つけられない** | 「レイヤー切替と発火を同時に行う」型を足したら、内側のアクションが起動時許可リストに載らず**発火だけ**が拒否された。症状は「画面は切り替わるのにPCが切り替わらない」＝**元の不具合の左右反転**で、しかもサーバーログにしか出ない。防御機構が正しく働いた結果として壊れる、という教材 |
| 2 | **宣言されているのに一度も使われていないフィールド** | `deck.grid.rows` はスキーマの必須項目でRust構造体にもあったが、描画も検証も `cols` しか見ていなかった。「rowsを2にしてもDeckが2段にならない」で発覚。**型があることと使われていることは別** |
| 3 | **`send_key()` が press の直後に release を呼ぶ** | ゲームの十字キーを作ろうとして初めて「押しっぱなしができない」と判明。押しっぱなしを足すと、今度は**離し忘れでPCが操作不能になる**。切断時の強制解放が必須になる、という因果の連鎖 |
| 4 | **レイヤー番号は大きい方が勝つ** | 日本語モード表示レイヤー(3)に記号盤(2)と同じキーを足したら記号盤が壊れる。回避のため一部の強調を**JSONではなくCSS**で実装した。データ設計と表示設計の境界の話 |
| 5 | **CSS Grid の `1fr` は内容の最小サイズを下回れない** | 狭いWebViewで13列キーボードの右端が見切れた。`minmax(0,1fr)` を徹底する。縦分割でも同じ罠が出る |
| 6 | **正方形スロットは幅で大きさが決まる** | `aspect-ratio:1` のマス目を縦分割の上半分に置くと、行数が多いとはみ出す。**高さから1マスの上限を逆算**する必要がある。さらに下限44px（タップ目標）を切ると別の問題になる |
| 7 | **作者スタイルはUAスタイルシートに必ず勝つ** | `.pagedots{display:flex}` が `[hidden]{display:none}` を打ち消し、空の箱がflex gapぶんの高さを食っていた |
| 8 | **区画の重なりは「片方が消えた」ようにしか見えない** | パズル式の配置変更で最も起きやすい事故。だからロード時に拒否する設計にした |

**本の芯にすべき問い**: 「クライアントに何を送らせてよいか」。
このリポジトリは *クライアントが送ってよいのは位置IDだけ、意味の解決は必ずサーバー側* という
不変条件を最初に立て、以降の全機能をその制約の中で設計しています
（トラックボールの連続値だけは例外を切り、条件を明文化して裁定を取っている）。
**制約を先に決めると設計が楽になる**という実例として、そのまま1章になります。

## 4. 守ってほしいこと（重要度順）

### 4-1. 🚩 ユーザーの個人情報を本に載せない

リポジトリには**実在する個人のパス・IPが含まれています**。掲載前に必ず伏字化してください。

### 4-2. コードを創作しない

**本に載せるコードは、すべてリポジトリから引用してください。**
「分かりやすくするための書き換え」をした場合は、その旨を明記してください。
`cargo test --workspace` が通らないコードを本に載せないこと。

### 4-3. 事実を盛らない

- **Windows専用です。** SendInputに依存しており、macOS/Linuxでは動きません。
  「クロスプラットフォーム」と書かないこと
- **`crates/hub-core/` は vendored 凍結コピー**です。このプロジェクトで設計したものではないので、
  自作部分として解説しないこと（`CLAUDE.md` に変更禁止と明記）
- **実機での未確認事項があります**（§5）。「実機で動作確認済み」と一律には書けません

### 4-4. セキュリティの書き方

この題材は **「ネットワーク越しにPCへキー入力を注入するアプリ」** です。書き方を誤ると、
そのまま攻撃ツールの作り方になります。次を必ず本文に入れてください。

- **LAN内・自分のPC専用**であること。インターネットに露出させる構成を書かないこと
- token認証・許可リスト・ロード時検証は**飾りではなく必須**である理由
- 「クライアントは位置IDしか送れない」という設計が、なぜ攻撃面を小さくするのか
- 逆に、**トークンが漏れたら何ができてしまうか**（正直に書く）

チュートリアルとして「とりあえず動かす」ために認証を外す手順は**書かないでください**。

### 4-5. リポジトリを書き換えない

CODEXは**本の原稿だけ**を作ってください。
`CLAUDE.md` の凍結領域（`crates/hub-core/`・`keymaps/keymap_default.json`・`brief/` の既存設計書とモック）は

## 6. 案Bを選ぶ場合 — Tauri章について

Tauriを足す価値は**確かにあります**。現状のUXにはこういう弱さがあるからです。

- Hubの起動が `start_hub.cmd` のダブルクリックで、**黒いコンソールが出しっぱなし**になる
- tokenが**コンソールに表示されるだけ**で、閉じると分からなくなる
- 設定GUI（`P-005` 段階D の「配置をパズルのように変える画面」）が未実装で、
  **今はJSONを手で書く**しかない（`docs/HUB_MANUAL.md` がその手順書）

Tauriで包めば、ウィンドウにQRを常時表示・トレイ常駐・自動起動・設定GUI・インストーラ配布が
自然に載ります。**ただし、これは新規実装であって既存コードの解説ではありません。**

守ってほしい線引き:

1. **先に実装し、動かしてから書く。** 未検証のコードを本に載せない
2. 実装は `brief/proposals/` に提案書を起票し、**ユーザー裁定を取ってから**着手する
   （`CLAUDE.md` が確定アーキテクチャの変更に提案を要求しているため）
3. 本文では「第V部までは動いているコードの解説、第VI部はここから作る話」と**明確に区別**する
4. Hubのコア（axum＋WS＋SendInput）は**そのまま使える**ことを示す。
   Tauriは「包み紙」であって作り直しではない、という構図が読者にとって一番有益
