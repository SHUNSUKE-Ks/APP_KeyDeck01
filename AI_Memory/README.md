# AI_Memory — 次に入るAIへの引き継ぎ置き場

チャットは消える。ここは消えない。**次のセッションはここから読む。**

## 読む順

| # | ファイル | 何が書いてあるか |
|---|---|---|
| ① | `引継ぎ.md` | **いまどうなっているか。** 上書き式。過去は書かない。迷ったらまずこれ |
| ② | `作業ログ/` | **なぜそうなったか。** 積み増し式。1セッション1枚。消さない |
| ③ | `../CLAUDE.md` | 憲法。凍結領域・不変条件。違反する変更は書く前に止まる |
| ④ | `../DEVBOARD.md` | 全履歴の正本。決定・検証記録を時系列で全部。**長いので、必要な日付だけ読む** |
| ⑤ | `../INDEX.md` | ファイルの地図 |

## なぜ2種類に分けてあるか

「いま」と「なぜ」を同じ紙に書くと、読むたびに全部読む羽目になる。

- **引継ぎ.md は毎回まるごと書き直す。** 古い話が1行も残らないので、短いまま保てる
- **作業ログは足すだけで直さない。** 当時の判断をあとから書き換えない

## DEVBOARD.md との違い（写しを作らないこと）

`DEVBOARD.md` が履歴の正本で、**技術的な詳細はそちらにしか書かない。**
ここに同じ説明を書くと、片方だけ直って必ずずれる（CreatorHub の AGENTS.md「分裂させない」）。

ここに書くのは、DEVBOARD を読んでも分からないことだけ:

- いま手を止めている場所と、その次にやること
- **確認できていないこと**（これが一番大事。嘘の前提で次の人が進むのを止める）
- ユーザーが口頭で決めたが、コードにもDEVBOARDにも残らない方針

## 書き方

```
作業ログ/YYYY-MM-DD_<やったこと>.md
```

1セッション1枚。長くしない。詳細は DEVBOARD の日付を指す。
