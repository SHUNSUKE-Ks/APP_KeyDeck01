## 決めたこと（なぜそうしたか）

### 二層ラジアルの判定は「角度＝どの扇 / 距離＝どの輪」の2つだけ

参考画像（外周＝大分類・内周＝細かい操作）をそのまま物差し2本に落とした。
タイミング（長押しの秒数）を judge に持ち込まないと決めた。**指はタイミングを外す。**
外へ出しすぎても最後の扇を保つので、思い切って払ってよい。

### 端の区画に置いたラジアルが暴発する問題

メニューは全体が見えるように**内側へ寄って開く**。つまり押した指は最初から
どれかの扇の上に乗っている。そのまま決まると「触っただけで発動」になる。

→ **12px 動かすまで何も選ばない（GRACE）。** 動かす向きは常に画面の内側なので、
端の区画でも全部の扇に届く。距離を判定に使う以上、
「見えている絵」と「判定の中心」を一致させる必要があり、その副作用として出た問題。

### 凍結は「描画ファイルの写し」まで取る

トラックボール Vol1.1 は生の `components.js` を読んでいて、**凍結が甘かった**。
今回は `components_v1_1.js` を作り、`editor_v1_1.html` / `keys_v1_1.html` に
そちらを読ませた。生の描画をいくら直しても、保存版は変わらない。

実際に開いて、保存版のナビが**古いまま**（PC部門とゲーム部門だけ）であることを確認した。
これが凍結できている証拠になる。

### 部品カタログは1か所へ

Deck編集にも「動作の見本」が要る。`keys.html` から写すと必ずずれるので、
`components.js` へ出して両方から呼ぶ（CreatorHub の AGENTS.md「分裂させない」）。
keys.html は101行減った。

### 部門＝画面の束ではなく、持ち物への入口

ゲーム部門に専用の編集画面を作らなかった。道具はPC部門と同じものを使い、
**ナビからはゲーム用の中身（盤面・keymap・deck）へ直接入る。**
Loupedeck の Profile と同じ考え方。部門が増えても直す場所が増えない。

### タイルの地色は `#rrggbb` だけ通す

CSSへそのまま入る値なので、**読み込みが唯一の関門**。`url(...)` などを
入れさせない。見た目だけの項目で、何が起きるかには一切関わらない（不変条件1は無関係）。
空きタイルには塗らない ――「置ける場所」と「置いてある物」を色で分けるため。

## 検証のやり方（本物のHubを止めずに試す）

本物の Hub（8770）はユーザーが使っているので止めない。exe もロックされていて
`cargo build` が通らない（`cargo check` は通る）。

代わりに **偽Hub** を別ポートに立てた:

```
C:\Users\...\scratchpad\hubstub\stub.mjs   ※一時。消えている可能性がある
```

やっていること:

- `static/` をそのまま配る（ルートは本物と同じ `/` `/keys` `/deckedit` …）
- `keymaps/keymap_*.json` と `layers/*.json` を1つに合体して `surface.config` を作り、
  WebSocket 接続直後に1回流す
- POST は本物を呼ばず、**受け取った本文をファイルに落とすだけ**
- `/api/icons` `/api/theme` `/api/defaults` も返す

**つまずいた点**: `surface.config` の種別欄は **`type`**（Rustの `#[serde(tag = "type")]`）。
`t` で作ったら画面が無反応になり、原因に時間を取られた。
アクションの `{"t":"key"}` と紛らわしいので注意。

### 何を確かめたか

- 二層ラジアル: 実ドラッグで 外周上=N・内周上=N2・内周左下=SW2・外周右上=NE。
  動かさず離す／中心で離す＝何も送らない。開いたメニューが body に残らないこと
- Deck編集: 実クリックで タイル選択→色→保存。**送られたJSONを取り出し、
  一時的に `decks/` へ置いて `cargo test` を通した**（本物のRustの読み込みで検証）。
  説明文が残り、色が付いたタイルだけ増え、他は無変更。確認後すぐ消した
- ゲーム盤面3枚: 編集画面で「✓ 重なり・はみ出しなし」。
  iPhone 7 縦の実寸（375×553）で描いて目視
- 保存版2画面: 自分の `components_v1_1.js` を読み、古いナビが出ること

`cargo test` 全通過（91＋46＋8＋7）。
