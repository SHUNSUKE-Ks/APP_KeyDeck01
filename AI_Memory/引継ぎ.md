## 2. いまの姿（V2.1）

### 画面（PC側）

| 部門 | 画面 |
|---|---|
| PC部門 | レイアウト編集 `/` ／ キー編集 `/keys` ／ **Deck編集 `/deckedit`** ／ 接続 `/connect` ／ 操作カタログ `/catalog` ／ スキーマ `/schema` ／ 設定 `/settings` |
| **ゲーム部門** | 盤面 iPad / iPhone横 / iPhone縦 / 空の軌跡 ／ アクション編集 ／ 移動キー編集 ／ 道具Deck編集 |
| 保存版（View_Ver1.1） | `/editor_v1_1` ／ `/keys_v1_1`（**凍結。触らない**） |

**部門＝画面の束ではなく、自分の持ち物への入口。** 編集画面はどの部門でも同じものを使う。
だから部門が増えても直す場所は増えない。ここを取り違えて部門ごとに画面を複製しないこと。

### 凍結してあるもの（変更禁止）

```
crates/hub-core/                 vendored
brief/ の設計書                   D番号の出どころ
keymaps/keymap_default.json      既定
Vol凍結版キーマップ                複製して新Volを作る
static/trackball_v1_1.html       トラックボール Vol1.1
static/editor_v1_1.html          ← 2026-09-23 追加
static/keys_v1_1.html            ← 2026-09-23 追加
static/components_v1_1.js        ← 2026-09-23 追加。上2つ専用の描画
git tag format-*
```

`*_v1_1.html` は **`/components_v1_1.js`（同じ日の写し）を読む。**
生の `components.js` をいくら直しても、この2画面は変わらない。そういう作りにしてある。

### 書き込みが許されている場所（4か所。増やすにはユーザー裁定が要る）

```
keymaps/layers/                レイヤーの中身
layouts/layout_<id>.json       board
keymaps/keymap_<id>.json       キーの位置（board）だけ。layerFiles は絶対に受け取らない
decks/deck_<id>.json           Deckのタイル ← 2026-09-23 追加
```

どれも **id がファイル名になる**ので、パスを組み立てる**前に** id の形
（`[a-z0-9_]{1,64}`）を見るのが唯一の関門。ここを緩めると任意のファイルを上書きできる。
保存の手順は4本とも同じ: スキーマ検証 → `.bak` 退避 → 書く → **全体を読み直す** → 落ちたら巻き戻す。
