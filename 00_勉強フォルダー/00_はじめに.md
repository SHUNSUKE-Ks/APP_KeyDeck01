# はじめに — このフォルダの使い方

このフォルダは、APP_KeyDeck01 を「1fileずつ・1行ずつ」読んで勉強するための
補助教材です。コード本体やDEVBOARD・briefなどの正式ドキュメントは一切変更しません
（このフォルダの中だけで完結します）。

## 中身

- `01_読む順番.md` … どのファイルをどの順で読むか。理由つき。上から順に読めば、
  依存関係の少ないものから多いものへ、データ形式→コアロジック→サーバ→画面、
  と無理なく積み上がるようになっています。
- `notes/` … 個々のファイルの「勉強コメント」。1ファイル（またはごく近い数ファイルの
  グループ）につき1枚。以下の型で統一しています。
  - **役割** … このファイルは何のために存在するか（1〜2文）
  - **前提** … 読む前に知っておくと迷わないこと
  - **読みどころ**（行番号つき） … どこに何が書いてあるか。実際にエディタでその行を
    開いて確認しながら読んでください
  - **なぜこうなっているか** … 設計上の理由（コード中のコメントや `CLAUDE.md` の
    不変条件に基づく。当てずっぽうは書いていません）
  - **理解度チェック** … 自分の言葉で説明できるか試す2〜3問

## 全体像（先に頭に入れておくと迷わない）

```
[iPad / スマホなどのブラウザ端末]                 [このPC = Hub]
  static/*.html (素のHTML+JS)  <--- WebSocket --->  crates/proto-hub (axum)
     - 押した/回した操作を                              - 状態を一元管理(state.rs)
       「位置ID」だけで送る                             - 位置ID→意味 をkeymap/deck/
       (key.press / deck.press /                        layout/surfaceの許可リストで解決
        surface.state / surface.gesture)                - proto-keymap: レイヤー解決(D3)
                                                          - proto-adapter-win: 実際に
                                                            Windowsへキー/マウス入力を送る
                                                          - hub-core: コマンドの冪等/拒否判定
                                                            (vendored凍結)

[keymaps/*.json, decks/*.json, layouts/*.json, surfaces/*.json]
  = 「何を表示し、何を送るか」の正体。コードを変えずにここを書き換えるだけで挙動が変わる。
```

つまりこのプロジェクトの一番大事な設計思想は、

> **ブラウザ端末は「どこを押したか」しか言えない。「それが何を意味するか」は
> 必ずPC(Hub)側のJSONだけが決める。**

という1点（`CLAUDE.md` の不変条件1）です。読み進めるときも、常に
「これは位置IDか？意味か？」を自問すると理解が早くなります。

## 読み方の推奨

1. まず `01_読む順番.md` を開き、今日読む1ファイルを決める
2. 実際のファイルをエディタで開く
3. 対応する `notes/` のカードを横に置きながら、行番号を照らし合わせて読む
4. 理解度チェックに（頭の中でよいので）答えてみる
5. 分からなかった点はメモしておき、後で聞く（このフォルダには書き込まなくてよい）
