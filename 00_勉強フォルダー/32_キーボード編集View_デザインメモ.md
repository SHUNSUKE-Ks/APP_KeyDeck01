## 1. 3案それぞれの狙い

### A案「ガイド」… 機器の絵＋引き出し線
TourBox の Guide 画面に一番近い形。中央に機器の絵、左右に説明パネル、両者を細い線で結ぶ。
部品を選ぶと右から編集パネルが出てきて、絵が少し小さくなる（焦点が絵から編集に移る）。

- **得意** … 「どのボタンが何をするか」の全体像。人に見せる・印刷する・説明する用途。
- **不得意** … 情報の密度。部品が増えると線が交差し、パネルの縦が足りなくなる。
  今の15部品で、1180×820 の縦がちょうど埋まる（左右6枚ずつに自動で振り分けている）。
- 線は**毎回その場の座標から引き直している**ので、部品の位置を変えても線は勝手に付いてくる。

### B案「カード」… 部品を種類ごとに並べる
機器の形を捨てて、部品を1枚1枚のカードにして並べる。上に「割り当て 16/17・空き 1・修飾で変わる 6」の集計。

- **得意** … 編集作業そのもの。空きがどこか、修飾で何が変わるかが**数と色で一覧できる**。
  「修飾中を見る」を押すと、上書きのあるカードだけ琥珀色で浮き、残りは沈む。差分の確認が一番速い。
- **不得意** … 手が覚えている位置と結びつかない。「左上の大きいボタン」を探すのに一拍かかる。
- カードの大きさは種類から決めている（ダイヤルは2列、十字キーは2×2）ので、部品を足しても並びは崩れない。

### C案「実機」… ラベルを部品に直接書く＋その場で開く編集
機器の絵を画面いっぱいに出し、割り当て名とキーを**部品の上に直接**書く。部品をタップすると、
その部品の真横に編集パネルがふわっと出る（左右どちらに出すかは空いている側を見て決める）。

- **得意** … 目の移動がほぼゼロ。編集画面と本番画面の形が同じ。押した感触・ダイヤルの回り心地が一番よく分かる。
- **不得意** … 長い割り当て名は2行で切れる。編集パネルが他の部品に重なる（画面外に出さないための妥協）。

## 2. 一番良いと思う案 → **C案「実機」**（B案の一覧を補助に）

理由は1つだけです。**この機器は iPad そのもの**だから。

普通の左手デバイスなら、編集画面と実物は別物なので「絵」は案内図にしかなりません。
でも KeyDeck では、編集しているその画面が、そのまま本番で指を置く盤面になります。
だから編集画面も**本番と同じ配置・同じ大きさ・同じ手触り**であるべきで、
「B1 は左上の大きいボタン」という**読み替えが1回も要らない**のはC案だけです。

副次的な理由:

- 修飾キーを**左の親指で押したまま、右手で別の部品を触れる**。これが本番の持ち方そのもの
  （3案とも動きますが、部品が本番と同じ位置にあるC案だけ「練習」になります）。
- 割り当て名の長さが**その場で分かる**。A案・B案はパネルの幅で読めてしまうので、
  本番で2行に切れることに気づけません（実際いくつかの名前は6文字までに直しました）。

ただしC案だけでは足りない場面があるので、**B案を「点検用」として残す**のが良いと考えます。
セットを作り終えたあと「空きが残っていないか」「修飾で何が変わるか」を見るのはB案が速い。
A案は、人に説明する・記事や説明書に使うときの見せ方として取っておく価値があります。

## 4. ボタンの状態の一覧

画面下の帯に見本を並べてあります（通常／押下中／選択中／修飾中／空き／修飾で変わる）。

| 状態 | class | 見え方 | いつ |
|---|---|---|---|
| 通常 | （なし） | 天面＋3pxの側面＋落ち影 | 既定 |
| 押下中 | `.is-pressed` | `translateY(0.35cqw) scale(.97)`、側面が消え内側に影、**押した点から波紋**、強調色がふわっと光って420msで消える | 指が触れている間 |
| 選択中 | `.is-selected` | 強調色の輪郭（`outline` 2.5px / offset 4px）。説明パネル・カード側も同時に光る | 編集対象 |
| 修飾中 | `.is-mod` | 琥珀の内枠＋外側のぼんやりした光、文字も琥珀。**上書きのない部品は opacity .42 に沈む** | 「修飾中を見る」入／MOD押下中 |
| 修飾キー自身 | `.is-held` | 琥珀に塗りつぶし、沈んだまま | MODを押している間 |
| 空き | `.is-empty` | 天面と影を消して**破線の枠だけ**、文字は「空き」 | 割り当てなし |
| 修飾で変わる | `.has-mod` | 右上に小さな琥珀の点 | 修飾中の上書きがある（修飾を見ていないとき） |

**空きは「無いもの」ではなく「置き場所がある」**という見せ方にしています（破線の枠を残す）。
修飾中に沈める演出は、修飾で**何が変わらないか**を見せるためのものです（透過＝通常と同じ）。

## 5. iPad で指が届く範囲について考えたこと

前提 … 1180×820 の横向き。両手で端を持つか、机・スタンドに置いて右手で触る。

- **修飾キーは左下**に置きました。両手持ちのとき左の親指が自然に乗る場所です。
  ここを押したまま右手で他の部品を触れるので、「修飾中を確かめる」が**手だけで完結**します。
  （C案では本番と同じ位置なので、編集がそのまま練習になります）
- **編集パネルは右**。右手（またはペン）で操作する想定。C案は選んだ部品の**空いている側**に出しますが、
  部品が右寄りのときは左に出るので、そこだけは一貫しません。**左手で押さえ、右手で編集**という
  持ち方を優先しました。
- **触るものは最低44px**（`--hit`）。入力欄・チップ・タブはすべてこれ以上。
  キーキャップの見本（`.kc`）のような**見るだけのもの**は小さくしてよい、と割り切っています。
- **ダイヤルは指で回せる大きさが要る**。C案で大ダイヤルは直径 約305px、小ダイヤルは約152px。
  外周を親指でなぞって回すので、目盛り（15°＝1周24目盛り、小は20°＝18目盛り）でも指が追いつきます。
  つまみは目盛りの間だけ指に少し遅れて付いてきて（`acc * 0.4`）、目盛りを越えると跳ねる。
  これが「かちっ」の代わりです（音は既定で切、♪で入る）。
- **上の帯（セット切替・案の切替）は指が遠い**。ただしセット切替は編集中に何度も押すものではなく、
  本番では機器の SET ボタンで切り替えるので、遠くてよいと判断しました。
  PC で触るときのために 1〜5 キーでもセットを切り替えられます。
- **二本指の同時操作**を前提に作ってあります（`touch-action: none` ＋ pointer capture）。
  ピンチや二本指スクロールで画面がずれないようにもしてあります。

## 6. 中身の作り（移植するときに読む所）

- **データは `KEYDECK_DATA` 1つだけ**。`<script>` の先頭にあります。
  画面はすべてここから描いているので、差し替えれば見た目もそのまま変わります。
  - `device.parts` … 部品と位置。座標は **100×72 の機器の上の位置**（画面の px ではない）。
    ダイヤルは `cx, cy, d`、他は `x, y, w, h`。十字キーは `group` で `device.groups` の枠に入る。
  - `sets[].base` / `sets[].mod` … 通常 / 修飾中の割り当て。
    **`mod` に書いていない部品は通常へ透過**。`null` を書くと「修飾中は空き」。
    これは本体の `keymaps/layers/*.json` のレイヤーの考え方と同じにしてあります。
  - 動作は `action.t` で `chord`（キーの組み合わせ）/ `text`（文字）/ `mo`（押している間だけ切替）/
    `set`（セット切替）。本体の `t: "key" / "chord" / "mo" / "tg"` と対応させやすい形にしました。
- **描き直しの作法**。組み立ては案を切り替えたときだけで、あとは `bind()` で登録した小さな関数が
  文字と class だけを書き換えます。要素を作り直さないので、**押している最中に表示が変わっても
  沈んだ感触のアニメが途切れません**（修飾キーを押した瞬間に全部のラベルが入れ替わるのが、まさにこれ）。
- **実際のキー入力・通信・保存はしていません。** 「押して登録」だけは PC のキーボードを読みますが、
  読むだけでどこにも送りません。編集結果はメモリ上だけで、再読み込みで戻ります。

## 7. 正直に書いておく弱点

1. **A案の引き出し線は交差する。** 部品が密なので、どの向きから線を引いても他の部品の上を通ります。
   今は線を薄くして、**部品の中心に置いた丸**で終点を示すことで読めるようにしていますが、
   部品が20を超えると厳しいはずです。
2. **C案の編集パネルは他の部品に重なる。** 空いている側に出していますが、大ダイヤルのように
   右端の部品を選ぶと左側（十字キーの上）に出ます。何もない所をタップで閉じられます。
3. **B案の並びは「意味の並び」ではない。** 種類の順に詰めているだけなので、
   「よく使う順」に並べ替えたいという要望は別途必要になります。
4. **割り当て名は実質6文字まで。** 小さいボタンだと2行で切れます。データ側の名前はすべて
   6文字以内に直しましたが、本番のデータでも同じ制約がかかります（表示名の入力欄は16文字まで）。
