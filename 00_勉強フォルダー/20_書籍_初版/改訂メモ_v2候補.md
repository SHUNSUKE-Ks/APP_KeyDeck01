## A. 重大（初版の主張そのものが誤っている）

### A-1　第2章「token が漏れたら、何ができてしまうか」が誤り 〔監修#2・重大度 高〕

初版は「token があっても、JSON に書かれていないキーや任意の文字列は送れない」「被害の上限はボードに置いたものの合計」と書いた。**実装では両方できる。**

```
POST /api/layer/save は token だけで通る
  → 受け取った action をそのまま書く（vk辞書92種・入れ子の制限の範囲内なら何でも）
  → 直後に load_startup_data を呼び、s.command_registry = loaded.command_registry で
     **許可リストを作り直す**
  → 押せば飛ぶ
```

裏取り: `crates/proto-hub/src/ws.rs` の `layer_save_handler`（804行〜、特に 896・931行）。

**直し方:** 第2章の該当節を「token は利用者の鍵ではなく、**編集権限つきの鍵**」と書き直す。
被害の上限は「ボードに置いたものの合計」ではなく「キーマップに書ける操作の全体」。第11章の保存APIへ参照を張る。
KeyDeck 側にも記録済み（`DEVBOARD.md` の B-002 の補足）。

### A-2　`layout.switch` / `app.launch` の入れ子が許可リストに載らない 〔監修#3・重大度 高〕

**これは原稿ではなく実装の穴。** 第13章が「入れ子のデータを足したら、許可リストを作る関数が中まで見ているかを確かめる」と学びを一般化しているため、読者は塞がれたと受け取る。

### B-4 の原因（2026-09-17 に切り分け済み）

```
トラックボールの区画は iframe（/trackball?embed=1）でできている（static/layout.html の renderTrackball）
  → 単発の chrome --headless --screenshot は、この iframe の中を描かないことがある
  → 待ち時間を 4 秒から 15 秒へ延ばしても、画像はバイト単位で同一（＝待ちの問題ではない）
  → /trackball?embed=1 を単独で撮ると、球は正しく描かれる
  → 同じボードを CDP（Page.captureScreenshot）で撮ると、球が写る
```

**実装の不具合ではない。撮影方法の問題。** 第6章の Fn の写真は CDP で撮っていたため影響を受けていない。
差し替え用の画像と、撮影に使ったスクリプトを `改訂素材\` に置いた。
