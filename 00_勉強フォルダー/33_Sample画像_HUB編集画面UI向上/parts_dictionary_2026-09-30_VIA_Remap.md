## 1. Keychron Launcher（トラックボール「Nape Pro」の設定・ダーク）

- **左サイドバー（縦長・暗色）**: 上にブランド名、デバイス選択カード（機種名＋接続状態「接続中」緑）、メニュー縦並び「カスタマイズ（選択中＝青背景）／DPI Settings／アドバンスモード／マクロ／新機種のアップデート」
- **上部**: 機種名、小さい状態チップ（電池 `69%`・`2.4G Mode`）、右上に丸アイコン2つ（言語・設定）
- **レイヤー選択**: 本体図の左上に縦の番号列 `Layer 0〜7`（選択中の0が白背景）
- **本体図（主役）**: デバイスを**写真のようなレンダー**で中央に大きく描く。黒い筐体、中央に**光沢のある黒い球**（上部に強いハイライト、縁に環境光の映り込み）、左に物理ボタン M1・M2、四隅に番号ボタン ①〜④
- **引き出し線のラベル**: 各ボタンから細い線が伸び、枠付きの小さい札に「今の割り当て」を書く（例: ボールスクロール／左クリック／右クリック／下スクロール・上スクロール／MO(1)／MEH(KC_NO)）。**図の上で「どこが何か」が一目で分かる**
- **ページ送り**: 本体図の下に ○● の2点（別アングル／別ページ）
- **リセット**: 右下に赤枠の小さいボタン
- **下段パネル（割り当ての部品棚）**: 横タブ「基本／OneShot／ショートカット／応答／同時押し／レイヤー／マクロ／トラックボール」、右に検索窓。上にマウス系の大きめボタン（左クリック・右クリック・ミドルクリック・戻る・進む・上下左右スクロール・左ダブルクリック・ボールジェスチャー・ロールスクロール）、下に**キーボード配列そのままの小キー群**（押したいキーを配列上で選ぶ）

- **最上部**: 中央にアイコンタブ4つ（キーボード＝選択中はピンク背景／聴診器＝診断／ペイント＝見た目／歯車＝設定）、右に VIA ロゴ・Discord・GitHub

- **本体図**: 中央に**実物と同じ形の配列**（分割の隙間・段ずれもそのまま）。キーは暗い角丸、刻印は上段記号＋下段主文字の2段。**選択中のキーはピンク**で塗る（例: Esc・Enter）。背景は淡いグラデ

## 共通の文法（6枚から抜き出したもの）

| 文法 | 中身 | KeyDeck の今 |
|---|---|---|
| **上＝本体図、下＝部品棚** | 画面を上下に割る。上で「どこ」を選び、下で「何を」選ぶ | キー編集 `/keys` がすでにこの型（盤面で選ぶ→右の棚）。**棚が右にある**点が違う |
| **レイヤー番号の列** | 本体図の左上に `0 1 2 3`。選択中だけ白 | キー編集にレイヤーのセレクタはあるが、番号列ではない |
| **実物どおりの形** | 分割の隙間・段ずれ・トラックボールの球まで実物の形で描く | 盤面は実機と同じ `components.js` で描いている（同じ思想） |
| **選択は1色で塗る** | 選択中のキーだけをアクセント色で塗る（VIA＝ピンク、Remap＝紫の枠） | 選択は枠の強調 |
| **引き出し線の札**（Keychron） | 図の上に「今の割り当て」を線でつないで出す | DevLayer（Component説明書）の発想と同じ。設定画面には無い |
| **空欄と ▽ が棚の先頭** | 「何もしない」と「下へ素通し」をいつも最初に置く | KeyDeck にも `none` と `trans` がある。棚での位置は決まっていない |
| **2段表記**（Vial） | 1キーに「タップ」と「長押し」の2つの役目を上下で見せる | KeyDeck は1キー1役目（`tg.fire` を除く） |
| **キーテスター** | 押したキーを図の上で光らせる | 無い（Note Story 側にキー入力モニターがある） |
| **設定は行の一覧** | 名前｜右端にトグル・スライダー・選択 | `/settings` は見出しと一覧の縦積み |
| **暗い灰で統一、アクセントは1色** | 背景・本体・棚が同じ暗さの段違い。色は選択にだけ使う | 利用者の方針（暗い配色）と一致 |

## 利用者の問いへのメモ（2026-09-30・統括チャット）

### トラックボールを設定画面にきれいに出せるか

**出せる。3D（three.js）は要らない。** 方法は2つで、組み合わせるのがよい。

1. **CSS / SVG で描く球**（`35_見た目2案…html` の球体ボタンと同じ型）: 放射グラデーションで光沢、上に白いハイライト、縁に環境光。回すと模様が流れる。軽く、今の決まり（D2＝素の HTML/JS）の中で作れる
2. **1枚の画像**: Blender で質感の高い球（と筐体）を静止画にし、`static/` に置いて背景に使う。画像は「依存するライブラリ」ではないので D2 に触れない。Keychron の見た目にいちばん近づく
   - 画像を配るには、`/icons` と同じく配る場所を1つ決める必要がある（読み取り専用なので書き込み口は増えない）

リアルタイムに光の向きが変わる本物の 3D にしたいときだけ three.js が要り、そのときは D2 の緩和手順（報告→人が判断）に乗せる。

### 優先度・中: 1画面で「押している間だけ」キーボードのレイヤーを切り替える

**仕組みはもうある**（`mo`＝押している間だけそのレイヤー）。ただし**レイヤーの状態はキーマップごと**に持っている（`static/layout.html` の `layerStates[keymapId]`）。そのため:

- 1つのキーマップの中に Fn（`mo`）と文字キーがある一枚キーボード（例: `ipad01_vol13`）なら、**今でも動く**
- 盤面（layout）で、Fn を別の区画（別のキーマップ）に置いた場合、**その Fn を押しても隣のキーボード区画のレイヤーは変わらない**

「表示画面1つ丸ごとレイヤーを切り替える」にするには、**盤面全体で1つのレイヤー状態を持つ**か、**Fn が別の区画のレイヤーを指せるようにする**設計が要る。D3（レイヤーの意味の決まり）に関わるので、設計を先に決めてからにする。

### 優先度・低: 接続する端末を最大3台に（iPad＋Android 2台）

今の QR ギャラリー `/connect` は「どの端末にどの盤面を出すか」が分かりにくい。
**設定画面の形が決まってから**、VIA の左上の機種ピル（7SKB ▾）のように「いま編集している端末」を切り替える形で考える。
